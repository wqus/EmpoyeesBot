# Telegram Employee Training Bot

Стек: Python 3.12, aiogram 3, PostgreSQL, SQLAlchemy 2 async, Alembic, Docker Compose.

Бизнес-правила: последовательные уроки; тест урока с произвольным количеством вопросов и порогом >=80%; неограниченные пересдачи; итоговый экзамен 30 случайных вопросов, проходной 27/30; новая выборка на пересдаче; слабые темы из ошибочных ответов; owner через OWNER_TELEGRAM_ID; администраторы через одноразовые invite-ссылки; справочные материалы; история экзаменов и результаты в административной панели. Автоматическая рассылка результатов не включена.

Запуск: скопировать `.env.example` в `.env`, заполнить значения, затем `docker compose up --build -d`.

Токен и параметры окружения задаются только в локальном `.env`; файл исключён из Git и Docker-образа.


## Встроенный курс «Оазис»

В проект интегрирован предоставленный учебный курс из 10 уроков. На чистой БД после миграций команда `python -m app.seed_oasis` автоматически создаёт 10 опубликованных уроков, 50 вопросов мини-тестов и 50 активных вопросов итогового экзамена. Docker Compose запускает seed автоматически перед ботом.

Seed безопасен для повторных запусков: если в БД уже есть хотя бы один урок, он ничего не меняет и не перезаписывает контент, отредактированный через админ-панель. Для локального запуска: `alembic upgrade head && python -m app.seed_oasis && python -m app.main`.

## Проверки

Установка инструментов: `python -m pip install '.[dev]'`. Для полного прогона укажите `TEST_DATABASE_URL` на отдельный PostgreSQL и выполните `python -m pytest -q`. Без этой переменной интеграционные тесты явно пропускаются. Каждый интеграционный тест создаёт собственную случайную схему, применяет Alembic и удаляет только свою схему; существующие таблицы указанной БД не очищаются. Тестовому пользователю нужны права CREATE SCHEMA.

CI в `.github/workflows/tests.yml` запускает PostgreSQL, миграции в обе стороны, сверку схемы, runtime/E2E, coverage и аудит зависимостей. Подробные результаты и границы проверки: [аудит 24 сентября 2026](docs/AUDIT_2026-09-24.md).

## Состояние и эксплуатация

Поддерживается один процесс polling на токен. FSM хранится в памяти: незавершённые формы и мини-тест после рестарта начинают заново через `/start`; сохранённые результаты и незавершённый итоговый экзамен остаются в PostgreSQL. Проверки выполняются в сервисах, повторные Telegram updates фиксируются в одной транзакции с изменениями. Старая кнопка изменения статуса с того же сообщения не выполняется повторно; для нового действия нужно заново открыть карточку.

Перед обновлением сделайте `pg_dump` и проверьте восстановление в отдельную БД. Новая миграция `0006_runtime_integrity` добавляет ограничения результатов, одну активную попытку экзамена на сотрудника и журнал обработанных updates. Если в старой БД уже есть несколько активных попыток одного сотрудника или некорректные баллы, миграция остановится: такие данные нужно разобрать отдельно, история автоматически не удаляется.

Полный запуск после резервного копирования: `docker compose up --build -d`. Compose использует внутреннее имя `postgres`; PostgreSQL наружу не публикуется. Для запуска Python непосредственно на хосте нужен доступный PostgreSQL и соответствующий `DATABASE_URL`.

Записи `processed_updates` обеспечивают защиту от повторов и растут со временем. Их можно архивировать/удалять по `created_at` в отдельной регламентной задаче; удаление снимает защиту для соответствующих старых кнопок. Автоматическое удаление истории не включено.
